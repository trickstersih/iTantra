# Tamil VITS Android test branch

This branch adds a **test-only** adapter for the selected Coqui Tamil VITS ONNX candidate:
`05_all_convtranspose_int4_weightonly.onnx` (15.46 MiB).

It is kept separate from the iTantra/Piper-style models. Tamil alone loads the dedicated Coqui model bundle and uses the exact character-token IDs generated by the effective tokenizer. English and Hindi retain the existing MMS models; Bengali, Marathi, and Kannada retain their existing SYSPIN paths; the other four languages continue using iTantra VITS.

## Branch integration

This change is intended for `syspin-bengali-android-test`, preserving the tested SYSPIN Bengali, Marathi, and Kannada adapters. Tamil is an additional isolated Coqui VITS path and does not replace those models.

## Add the model asset locally

The model archive is intentionally not committed to Git. Copy the separately supplied `tamil-vits-test.zip` to:

`app/src/main/assets/models/tamil-vits-test.zip`

Create the `models` assets directory if it does not exist. The archive must contain:

- `.tamil-vits-test/tam/model.onnx`
- `.tamil-vits-test/tam/config.json`
- `.tamil-vits-test/tam/tokens.txt`

The supplied archive already has this layout and has been checked against all seven token-ID probes from the source environment. Its Coqui config contains bare `Infinity` values, which are not valid strict JSON; `TtsConfigReader` normalizes bare non-finite numeric values to `null` before Android `JSONObject` parses the config, while leaving quoted strings unchanged.

## Build and install (Windows PowerShell)

```powershell
git fetch origin
git switch syspin-bengali-android-test
# Copy tamil-vits-test.zip to app\src\main\assets\models\tamil-vits-test.zip first.
.\gradlew.bat clean :app:assembleDebug
.\gradlew.bat :app:installDebug
```

## Test

Keyboard-entered text is intentionally tagged as `und` and cannot be manually spoken by the app's message-playback button. For this smoke test, select Tamil (`ta`) as the speech language, create and send a short Tamil PTT voice message, then tap the playback button on the resulting transcript. This exercises the same production TTS engine path. Compare the generated speech against these reference sentences where practical:

1. `வணக்கம்.`
2. `தமிழ் ஒரு அழகான மொழி.`
3. `நீ எப்படி இருக்கிறாய்?`
4. `தயவுசெய்து எனக்கு தண்ணீர் கொடுங்கள்.`
5. `வானம் நீல நிறமாக இருக்கிறது.`
6. `இது மிகவும் சுவாரஸ்யமான புத்தகம்.`
7. `நாளைக்குச் சந்திப்போம்!`

Check Logcat for `MmsTtsEngine` messages. If the app cannot initialize the model, collect the complete exception, especially missing/unsupported ONNX operator or model-input messages.

The ONNX model was tested with desktop ONNX Runtime 1.31.0. This branch targets the project's Android ONNX Runtime dependency (1.30.0), but the APK/device inference still needs to be exercised on the target phone; Python success is not proof of Android execution or playback quality.

No app-side claim of audio quality is made by this branch until on-device playback has been checked. The embedding-quantized variant that produced gibberish is not used.
